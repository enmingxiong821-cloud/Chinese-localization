### C-01（最严重）C2「固化」路线已被文档自己作废，但前文未回收

- **冲突点**：`技术设计 §六` 结论「推荐 **C1 起步 → C2 固化**」，并在选型表里把 C2 描述为可行路线；同一文档 `§12.1` 实测 ACL 后判定「**C2 不能被写入，C2 作废**」，把「固化」重新定义为**持久化启动器**。
- **代码证据**：无任何 ACL 写入或安装目录写入代码；`inject-claude.mjs:109-110` 明示 `persistent:false`、`installFilesModified:false`；无持久化启动器。
- **影响**：读者若只看 §六 会误以为有 C2 落盘路径。以代码与 §12.1 为准：**只有 C1**。

### C-02 scanner 路径与 version 结论，前后两版文档相反

- **文档说 X**：`双应用首批范围.md §Claude只读探测` 称 `resources/app/package.json` 返回 `missing/ENOENT`，扫描报告 `version` 仍为 `null`、`compatibility` 为 `not-verified`，并把「Claude 真实安装路径与资源扫描尚未执行」记为未完成。
- **代码实际 Y**：`scanner.mjs:23`（`locateAppRoot`）已下钻到 `app/` 子目录，`scanner.test.mjs` 有「WindowsApps 包根下钻 / app 为链接不下钻」用例；`技术设计 §11.1` 也承认旧结论是路径拼错（曾误记「未实现」）。
- **结论**：以代码为准，旧文档结论**已作废**。

### C-03 P0-01「缺目录总量约束与文件上限」已过时

- **文档说 X**：`汇总 TXT P0-01` 定位 `candidate-artifacts.mjs:30-40`，称「目录递归没有文件数、深度、总字节上限」「读前检查 size 随后 readFile 至 EOF」。

## 五、优先级建议

### 5.1 地基未浇好——现在加会返工

1. **真实 Claude Desktop 端到端验证（层 C 注入）**。这是整个 Claude 汉化量产的判据。当前「解码链通没通」只有 headless Chrome fixture 证据（`inject-claude.test.mjs`），真实 bundle 的加载时序、CSP、自定义协议下 `localStorage` 可用性均未实测（`技术设计 §12.6 #1` 自认）。**在此之前任何大批量译文、持久化启动器、页面验收都建立在未验证的假设上。**
2. **`zh-CN` / `zh-Hans` 命名统一（C-12）**。候选、资源文件名、report、注入键名四处的语言标识必须在**落盘前**统一；不统一则所有既有候选与审核产物都要重打。
3. **门禁与备份「有人消费」**。`install-identity.mjs` 与 `backup-transaction.mjs` 都已实现却无调用方（C-04/C-15）。任何真实写入前必须先有一个编排层把它们串起来（预检→复验→备份→按计划写入→验证），否则门禁形同虚设。
4. **受控 I/O 硬超时 + 统一 Schema 校验**。安全边界（P0-01 残留的硬超时、P0-02 竞态、P1-06 Schema）是后续所有读写模块的公共底座；先做能避免各模块各自打补丁。
5. **目录结构与 TS 工程收敛（C-07 / §2.9）**。`drivers/` `core/` 与 React 工程越晚定，模块搬迁成本越高。建议先定结构再迁移，不要一边加功能一边平铺。

### 5.2 可独立推进——不依赖上述地基

1. **Cursor 路线**：VSIX 打包 + 引擎范围核对 + 稳定写回映射（P1-01）。与 Claude 完全解耦，且 `cursor-pack.mjs` 已就绪。
2. **审核体验与审计链**：审核页分页/虚拟化、机器可读差异预览、Claude 派生候选统一报告（P1-02）、Schema 化（P1-06）。纯数据/前端域，低耦合，能显著提升 34,213 键的可维护性。
3. **翻译质量核心与术语/TM**（TS 共享核心）：`translation-quality.mjs` 换成成熟 ICU 解析器，术语库与翻译记忆先与具体应用解耦。
4. **原型接真实只读链路**（P1-05）：`prototype/app.js` → 真实 `scan` 只读结果，错误/权限/未知版本不得报成功。风险低，能尽早暴露 UI 需求。
5. **持久化启动器**（C2 作废后的「固化」）：独立小工具，可先于其他功能单独交付。
6. **实时翻译 / OCR / 覆盖层**：是**正交的第二条产品线**，建议先在独立原型里验证取词与延迟，**不要与 Claude 汉化并行开工**——否则会在「通用多端」上同时维护多个未完成入口（`汇总 TXT §十一` 警告的原话）。

### 5.3 一句话排期

先做 5.1 的第 1、2、3 项（真实注入验证 + 命名统一 + 门禁/备份编排），这是「一台指定版本 Claude 的真实可加载、可恢复闭环」的最小地基；其余应用汉化、实时翻译、插件都排在其后，避免把地基未稳的假设扩散到更多模块。
