提交到 GitHub 时，不要提交"我自己推理出来的废话"——即推断过程、试错流水、
"我一开始以为…后来发现…"式的自我叙述、以及对未验证可能性的罗列。

**Why:** 用户 2026-10-14 在浏览仓库页面时明确提出。此前写入 `doc/` 的设计文档与
实测报告里混了大量推导与踩坑叙事（如"校验器本身修过三次""该判断有误，已纠正"），
这些属于过程记录，不是交付物。

**How to apply:** 写进仓库的文档只保留三类内容 —— 结论与实测数字、使用方法/还原步骤、
已知残留与边界。推导路径、失败尝试、心路历程留在对话里，不入库。
新增 doc 前先自问"读者要按它做事吗"；不能的就不写。
